# PlayZone Manager SaaS Cloud Core

First isolated SaaS foundation for PlayZone Manager. It is intentionally separate from the current cashier production service while the migration is built and tested.

## Included in this milestone

- Multi-tenant customer model (`Tenant`) with one `MAIN` branch created automatically.
- Customer-scoped users: `OWNER`, `MANAGER`, `CASHIER`.
- Platform-level `PLATFORM_ADMIN` that is not attached to a customer.
- Customer codes such as `PZM-0001`.
- One-time Installation Codes generated by the platform admin.
- Edge Device registration with a separate device identity/token.
- Device revoke, heartbeat, version and last-seen tracking.
- Idempotent Edge Event ingestion using `(device, event_id)` and `(device, sequence)` uniqueness.
- Customer overview is tenant-scoped from the authenticated user token; callers do not submit `tenant_id` to select another customer's data.
- PostgreSQL-ready via `DATABASE_URL`; SQLite remains supported for automated tests/local development.

## Environment

- `DATABASE_URL`: PostgreSQL in production, e.g. supplied by Railway. `postgres://` and `postgresql://` are normalized to psycopg automatically.
- `PLAYZONE_PLATFORM_ADMIN_USERNAME`
- `PLAYZONE_PLATFORM_ADMIN_PASSWORD`

## Initial API flow

1. Platform admin signs in without a customer code.
2. Platform admin creates a customer; Cloud creates `PZM-xxxx`, `MAIN` branch and OWNER.
3. Platform admin creates a one-time Installation Code.
4. Edge submits that code once and receives `device_id + device_token`.
5. Edge uses the device credentials for heartbeat/config/event sync.
6. Customer users sign in with their customer code and only receive that tenant's data.

This milestone does **not** replace the current PlayZone Manager v0.27 cashier/Voltra runtime yet. The next milestone connects the local Edge runtime and offline event queue to these APIs.


## Edge transition status

The transitional v0.27 bridge is kept under `saas/edge/integration/v027_edge_runtime.py`.
It copies only **committed** local audit actions into a durable Edge outbox, uses deterministic
`audit-<id>` event IDs, and keeps cloud sync completely off the cashier transaction path.
Customer Windows builds protect the Edge device token with machine-scoped Windows DPAPI.
