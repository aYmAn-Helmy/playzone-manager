PlayZone Manager v0.34.5 — Client Acceptance
================================================

- الموظف يفتح وردية واحدة فقط للدرج وتبدأ برصيد نظامي صفر.
- لا يمكن وجود ورديتين OPEN لنفس الدرج في نفس الوقت، مع قيد داخل قاعدة البيانات لمنع الطلبات المتزامنة.
- STAFF لا يستطيع تسجيل Cash In أو تغيير رصيد بداية الوردية.
- أي Cash Out / مصروف يتحول إلى طلب PENDING ولا يخصم من رصيد الدرج.
- أي حركة نقدية لا تصبح فعالة إلا بعد إدخال اسم وباسورد ADMIN/ROOT واعتمادها.
- يمكن للمدير رفض الطلب المعلق بدون تأثير على رصيد الدرج.
- اعتماد المصروفات وتصفية الدرج يتمان بالتتابع لمنع Race Conditions على الرصيد.
- لا يمكن إقفال الوردية طالما توجد مصروفات معلقة.
- يمكن للمدير تصفية وإقفال الدرج حتى مع وجود جلسات RUNNING / PAUSED / EXPIRED؛ الجلسات تستمر كما هي، وأي فاتورة يتم تحصيلها لاحقاً تدخل على الوردية المفتوحة وقت الدفع.
- تصفية الدرج وإقفال الوردية تتطلب إعادة إدخال باسورد ADMIN/ROOT حتى لو المدير أو الموظف مسجل دخوله بالفعل.
- يسجل النظام المدير الذي اعتمد الحركة والمدير الذي أغلق وصفر الوردية.
- يمكن للموظف الحالي تسليم الوردية لموظف STAFF آخر؛ الموظف المستلم يجب أن يختار حسابه ويدخل باسورده بنفسه.
- بعد نجاح التسليم ينتقل مالك الوردية للموظف المستلم ويتم إبطال جلسات تسجيل الدخول القديمة للطرفين وإصدار Token جديد للمستلم على جهاز الكاش.
- تسليم الوردية لا يصفر الدرج ولا يوقف الجلسات ولا يفقد المصروفات المعلقة؛ كل شيء يستمر داخل نفس الوردية مع سجل مستقل للتسليم.
- كل تصفية للدرج تنشئ سجل Drawer Settlement ثابت برقم متسلسل، التاريخ، الموظف، المدير، رصيد النظام، العد الفعلي، الفرق، وعدد الجلسات التي كانت مستمرة وقت الإقفال.
- صفحة التقارير تعرض تسلسل تصفية الدرج وسجل تسليم الورديات ضمن الفترة المحددة.
- STAFF لا يستطيع تصنيف فاتورة على أنها InstaPay أو Visa بدون إعادة إدخال باسورد ADMIN/ROOT؛ Cash يظل المسار العادي للموظف.
- الخصومات تظل ADMIN/ROOT فقط من الـBackend.
- لا توجد Routes لتعديل أو حذف فاتورة قديمة أو تغيير طريقة دفعها بعد الإصدار.
- المحاولات المتكررة الخاطئة لتسجيل الدخول أو اعتماد المدير عليها Rate Limit مؤقت.
- كل القيود مطبقة من الـBackend وليست مجرد إخفاء أزرار من الواجهة.

حماية ملفات البيانات على Windows
--------------------------------
- قاعدة البيانات وVoltra والـBackups تنتقل عند Upgrade إلى:
  C:\ProgramData\PlayZone Manager\secure-data
- secure-data يسمح بالوصول فقط إلى LocalSystem وAdministrators.
- Windows Service يعيد التحقق من ACL عند كل تشغيل.
- desktop-profile والكاش يظلان خارج secure-data حتى يعمل تطبيق PlayZone للمستخدم العادي.
- إذا وجد الـInstaller قاعدة legacy وقاعدة secure في نفس الوقت فإنه يوقف التثبيت بدلاً من اختيار قاعدة عشوائياً.

إصلاحات Client Final v0.34.2
----------------------------
- إصلاح حزمة الـOffline Runtime التي كانت تحذف typing_inspection من الباكدج النهائية بسبب فلتر تنظيف واسع.
- إضافة فحص مبكر داخل Bootstrap-Portable.ps1 للتأكد من وجود الـwheels الحرجة قبل بدء تثبيت Python.
- إضافة Uninstall-PlayZone-Service.bat واضح للعميل مع طلب صلاحيات Administrator تلقائياً.
- الـInstaller ينسخ ملفات الـUninstall إلى C:\Program Files\PlayZone Manager أثناء التثبيت.
- Build العميل النهائي يختبر تثبيت Python فعلياً من الـpackage المنظفة باستخدام --no-index قبل إنشاء ملف ZIP.

إصلاحات واجهة التشغيل v0.34.3
-----------------------------
- إصلاح بدء الجلسة: أزرار تشغيل/إدارة الجلسات أصبحت تتطلب وردية مفتوحة لكل الأدوار بما فيها ADMIN/ROOT، بما يطابق حماية الـBackend.
- إذا لم توجد وردية، يظهر تنبيه واضح وزر فتح الوردية بدلاً من فتح مودال الجلسة ثم رفض العملية بعد الضغط على تأكيد البدء.
- تم اختبار زر "تأكيد البدء" داخل Electron فعلياً بعد فتح الوردية والتأكد أن الجلسة تتحول إلى RUNNING.
- إزالة الاعتماد على window.prompt من إدارة الموظفين لأن نوافذ Prompt لم تكن تعمل داخل Electron.
- إعادة تعيين كلمة مرور الموظف أصبحت من Modal داخلي، مع إلغاء Tokens الموظف وظهور حالة "مطلوب تغيير كلمة المرور".
- تعطيل/تفعيل الموظف أصبح من Modal تأكيد داخلي، مع منع تعطيل الحساب المستخدم حالياً من الواجهة.
- تم اختبار Reset Password وDisable وEnable تفاعلياً داخل Electron والتحقق من النتيجة من الـAPI.
- تم تغيير Cache Key للـFrontend لضمان عدم تشغيل JavaScript قديم بعد Upgrade.

نسخة Client Acceptance v0.34.4
------------------------------
- إخفاء رصيد الدرج نهائياً من بطاقة "وردية مفتوحة"؛ البطاقة تعرض الحالة واسم الموظف فقط.
- تثبيت آخر إصلاحات بدء الجلسة وإدارة الموظفين وVoltra والـSidebar والـScrollbars.
- هذه النسخة مخصصة لاختبار قبول العميل النهائي وتُبنى كحزمة Offline كاملة مع Electron وPython Runtime وملفات Install/Uninstall.
- Build الإصدار يمر على اختبارات Backend وElectron UI وVoltra وOffline Runtime بالإضافة إلى تجربة تثبيت Windows Service ثم Uninstall.

إصلاح تثبيت وتشغيل سطح المكتب v0.34.5
-------------------------------------
- إصلاح إنشاء Shortcut بحيث يتم التحقق من Desktop الفعلي للمستخدم بما فيه Desktop redirected/OneDrive، مع fallback إلى All Users Desktop.
- الـInstaller يفشل بوضوح إذا لم يستطع إنشاء Shortcut صالح بدل ما يكمل بدون Shortcut.
- يتم التحقق من Target داخل ملف الـLNK بعد إنشائه للتأكد أنه يشير إلى PlayZone Manager.exe المثبت.
- تشغيل PlayZone بعد التثبيت يتم عن طريق Windows Shell كعملية مستقلة عن نافذة CMD/PowerShell الخاصة بالـInstaller.
- إغلاق نافذة التثبيت أو الـTerminal لا يجب أن يغلق تطبيق PlayZone Manager أو Windows Service.
- يظل هناك Shortcut في Start Menu وStartup إلى جانب Shortcut الـDesktop.

ملاحظات تشغيلية
---------------
- الطلب المعلق لا يعني السماح للموظف بإخراج نقد فعلياً؛ هو تسجيل طلب فقط إلى أن يوافق المدير.
- الفرق بين العد الفعلي ورصيد النظام يظل مسجلاً عند الإقفال ولا يتم محوه.
- الحماية البرمجية لا تمنع سرقة نقدية مادية خارج النظام أو بيعاً غير مسجل؛ ذلك يحتاج ضوابط تشغيلية مثل درج مقفول، إيصالات، كاميرات ومراجعة دورية.
